What each part of the application does

US-Agent supports preparing user stories, classifying their functional intent with a taxonomy, making human decisions, and reusing requirements or other artifacts through configurable recommenders.

Navigation / areaWhat to do there
My ProjectsOpen or create projects; inspect the profile, story counts, and cycles.
Project detailsSave stories, assign a sprint, prepare tasks and technologies, and inspect linked NFRs.
Classify StoriesSelect a taxonomy and execution mode; classify a saved story or import a batch of story text.
Review QueueInspect uncertainty, provenance, provider evidence when present, taxonomy gaps, and human decisions.
Classification history / DashboardFind processed stories and inspect totals, review workload, confidence and module distribution.
TaxonomiesInspect WIS modules and operations; create, review, and publish new versions.
RecommendersRun risk and NFR recommendations; inspect their sources; accept and adapt suggestions.
Configuration and datasetsDefine inputs, outputs and comparison settings; import and publish a reference dataset.
Access and auditAdministrator-only membership and audit controls; unavailable to the reviewer account.

3-minute application tour · no model call

Start with a project, story, and classification

  1. Open My Projects, then click P02.
  2. Select the organization-management story, US-86. You can also open it directly.
  3. Read the Classification labels and status. Scroll to Tasks and Linked NFRs. These are the story’s stored artifacts.
  4. Expand Project profile · P02 to inspect its classification taxonomy and project characteristics.
  5. Open Classification history. Search for P02 to find the two original examples.
  6. Open Dashboard to see the workspace’s current classification totals.

Expected result: you can follow a stored story from its project and prepared tasks to its classification and workspace overview.

Continue with sections 1–6 for the application workflow. The risk quick start is a separate, prepared recommendation exercise.

1 · Projects and project profiles

Find or create a project and set its context

  1. Open My Projects. Each project card shows Stories, To classify, and Cycles. A saved, unclassified story counts under To classify.
  2. Click P02, then expand Project profile · P02.
  3. Inspect Taxonomy for story classification, Platforms, Application domains, Purpose, Software architectures, and the technology tags.
  4. To edit a practice project, use P03. Enter a tag and press Enter or click its Add button; click its removal control to remove a tag. Click Save profile and expect Profile saved.
  5. To create another practice project, return to My Projects → Add project → enter a unique Project name → Create project. Use P03 if you want to follow the prepared exercises without creating a new project.

Expected result: a project opens with its own stories and profile. Updating its taxonomy choice affects future classifications; it does not reclassify existing stories.

2 · Saved stories, sprints, tasks, and linked requirements

Prepare a story before classifying it

  1. Inspect P02 → US-86. Select a story in Project stories to see its status, classification, tasks, and linked NFRs. Click an existing task to inspect its description, category, technologies, and Completed flag.
  2. Open P03 and click Add user story.
  3. Enter Sprint = Reviewer walkthrough. Paste the existing grade-consolidation story below into User story, then click Save story.
  4. The saved copy receives its own US-number and Not classified status. Keep that story selected. You can use Edit story before classification.
  5. In Tasks, click Add. Reuse the P02 task category and the adapted task description below for the grade-consolidation copy, then click Save. A task’s technologies complement the project profile.
  6. Confirm that the task appears under the saved story. Click Classify story to continue with this exact story and its prepared task.

3 · Classification and text import

Choose the taxonomy and execution mode

  1. Continue from your saved P03 copy using Classify story. The form loads its text, project, sprint, and prepared-task count.
  2. Under Run configuration, select Taxonomy = 1.0.0 and Mode = Local preview.
  3. Click Start classification. Wait for Classification saved.
  4. Inspect the proposed module/operation pair, confidence and Review badge. Click View project details to inspect the saved result, or open Review Queue to make a human decision.

For this exact story with Local preview and taxonomy 1.0.0, expect n/a / n/a, 35% confidence, and Pending review. The rule set does not recognize the grade-consolidation intent. This is a deliberate review exercise using our existing story text.

Local preview and Model committee are different executions. Local preview uses deterministic local rules without provider calls. Model committee uses the configured external model providers, can return multiple labels, and can fail or take longer. Its results and confidence may differ. The walkthrough does not treat the local 35% score as an empirical accuracy estimate.

Import or classify several stories

  1. Open Classify Stories from the navigation. Select project P03 and enter a sprint.
  2. Paste one story per line, or download our existing story texts and choose Import TXT/CSV.
  3. Inspect the loaded User stories text, story count, taxonomy and mode before clicking Start classification. The text-import control is separate from the structured recommender-dataset importer.

To preserve an already saved story and its prepared tasks, use its Classify story link. Reclassify story creates another classification for that saved story; it does not change the original source story in another project.

4 · Human review and taxonomy gaps

Inspect the evidence and confirm a classification

Use your newly classified P03 copy. A prepared pending copy is also available until another reviewer completes it.

  1. Open Review Queue and select the grade-consolidation story. Read Why this story needs review, its confidence, and any available consensus or uncertainty.
  2. Expand Run provenance. For Local preview, inspect the local engine/policy, taxonomy version/hash, preserved automatic result, and zero provider responses. Committee runs can additionally show Classifier suggestions, provider/model details, rationales, evidence, failures, and fallback suggestions.
  3. For this exercise, choose Domain = General, Module = Registry, and Operation = Retrieve data. Click Add pair. Check that it appears in Pairs to confirm. Remove an unsuitable pair with its Remove button.
  4. In Review notes, paste the reason below, then click Confirm classification.
  5. Open the P03 story. Expect Registry / Retrieve data and Reviewed. Its Classification history row uses the status badge Completed. Human review preserves the original run confidence; confirming the labels does not rerun the classifier. The confirmed item leaves the pending queue.
The coordinator must retrieve student grades before consolidating them. Confirmed against the existing grade-consolidation story and the selected WIS taxonomy.

When the taxonomy does not cover the story

Use Mark taxonomy gap if you cannot confirm valid pairs. To request clarification, open Suggest taxonomy evolution → Proposal type = Request story clarification. Enter a rationale, such as “Should the coordinator only retrieve existing grades, or also calculate the consolidated result?”, then click Save request. The request is recorded without changing the taxonomy.

The review form also exposes legacy domain/module/operation proposal controls. Those controls do not publish a preserved WIS version. For the versioned WIS editing exercise, use Taxonomies → Create a new taxonomy version, then classify a practice copy with that version.

Expected result: an auditable human decision or an explicit unresolved gap. If the queue is empty, repeat the Local preview exercise with a new copy; no fabricated model response is needed.

5 · Classification history and Dashboard

Find the processed story and inspect workspace totals

  1. Open Classification history. In Search classifications, enter P03, a phrase from the story, or Registry.
  2. Inspect each row’s classification pairs, confidence and status. Click the story text to open its project, or its review when pending.
  3. Open Dashboard. Inspect Classified stories, Average confidence, Pending review, and Automatically accepted.
  4. Read Recent classifications and Distribution by module. Use View all to return to Classification history.

Expected result: the reviewed P03 copy is discoverable and the dashboard reflects the current classification set.

Classification history lists the current classification for each processed story; it is not a browser for every past model invocation. Recommendation runs have a separate Run history. In this build, the counter labelled Automatically accepted includes both automatically accepted and human-reviewed stories. Dashboard confidence is an aggregate of stored scores, including local-rule scores where used, not a measured correctness rate or productivity result. Module counts can overlap for stories with multiple labels.

6 · Taxonomies and versions

Inspect WIS and publish reviewed changes as a new version

  1. Open Taxonomies. Search for WIS. The prepared active version is 1.0.0; Include retired versions reveals preserved older versions.
  2. On WIS 1.0.0, click Open taxonomy. Expect Read-only version.
  3. Under Find a node, enter Retrieve data, then select that operation. Inspect its name, description, module, and identifiers.
  4. Expand Version reference and full content to inspect the exact content and hash.

Optional editing exercise

  1. Click Create a new taxonomy version. Keep the WIS identifier and enter an unused version, such as reviewer-1.
  2. Select a module or operation to edit its description, or use Add module / Add operation for a justified extension. WIS keeps two levels; operations belong to modules.
  3. Click Save taxonomy draft. Review the nodes and full content, then click Publish reviewed taxonomy.
  4. Open the practice project’s profile, select the new version for future classification, and click Save profile if you want to use it.

Expected result: a separately published version becomes selectable for new classifications and compatible recommender attributes. Previously recorded classifications and published recommendation dependencies retain their original version.

Other recommender areas and deployment availability

Test cases and custom KNN recommenders

Open Recommenders → Test cases. The interface retrieves existing test artifacts from compatible publications; it does not generate new test cases.

Current deployment: no test-case catalog, compatible test-case definition or reference dataset is published in the prepared workspace. The page therefore reports No compatible recommender has been published. This is the observed availability state, not a successful test-case recommendation.

  1. To enable this workflow, first publish a compatible definition and a test catalog through Configuration and datasets → Test catalogs, including its original test artifacts and use declaration.
  2. Import and publish compatible reference records with their test associations. Select the exact catalog and dataset publication used by the recommender.
  3. Return to Test cases, choose a classified story, complete the project profile and required acceptance criteria, and run the recommendation. Inspect retrieved source artifacts before accepting or adapting a separate copy.

My KNN recommenders exposes additional published project recommenders. Its configurable comparison features, weights, and associated outputs are managed through the configuration workflow below. Publishing a taxonomy or defining fields alone does not create a knowledge base of associated artifacts.

7 · Recommender definitions, reference data, and imports

Inspect or extend the configuration and publish a dataset

The prepared recommendation exercises already have their publications. Use this section to inspect them or practice importing a separate copy of our existing reference records.

Inspect a published definition

  1. Open Configuration and datasets → Definitions.
  2. Select Project Risk Recommender version 2 and click Load definition. Inspect each attribute’s name, type, scope, cardinality and role, then the calculation settings and weights.
  3. To extend this published configuration, click Create a new definition version, enter an unused version, and review its attributes and method settings. Use Save definition draft, followed by Publish reviewed definition. Existing published versions remain preserved.

Create a custom recommender with the wizard

  1. Open New recommender. In Name, enter a descriptive name, then click Continue.
  2. In Inputs, declare the project characteristics to compare, their names, types and cardinalities. Reuse the prepared risk configuration’s inputs if you want to reproduce that example.
  3. In Recommendations, name the associated output items. The reference projects must supply these outputs; defining a field alone does not supply knowledge.
  4. In Matching, set the number of neighbors and input weights. In Review, inspect the inputs, outputs and settings, then click Create recommender.
  5. Click Add reference data and complete an import or a reviewed dataset built from registered projects before running it.

Import the same prepared risk records into a new dataset

  1. Download our prepared risk-reference JSON. These are the existing three reference records used in this guide, including their explicitly synthetic risk and team-distribution associations.
  2. Under Import dataset, choose Import definition = Project Risk Recommender · project-risk-recommender · 2. Click Load dataset schema.
  3. Use Dataset ID = reviewer-risk-base, Dataset version = 1, and File format = JSON. If that version already exists, choose another unused version.
  4. In Source description, enter Copy of our prepared project-risk reference records. Set Use declaration = Synthetic demonstration. In Authorization reference, enter US-Agent prepared reviewer demonstration; risk and team-distribution associations are synthetic.
  5. Select the downloaded JSON file and click Use US-Agent record mapping. Inspect the Record ID path and each attribute’s source path.
  6. Click Generate import preview. Expect 3 valid records, 0 invalid, and 0 duplicate identities. Inspect mapped values and unmapped fields. Resolve issues or make explicit exclusions before publishing.
  7. Click Publish reviewed dataset. Then open Runs and history, choose the exact definition and new dataset publication, and enter the target profile from the risk exercise.

Expected result: a separately published dataset is available for compatible new recommendation runs. Labels and artifacts are imported as supplied; the import is not a new story-classification run.

For custom project KNN, Build from registered projects can prepare reference profiles, but you must review and supply their associated recommendation outputs. The download-example control provides a synthetic template, not newly observed project evidence.

Scenario 3 · About 1 minute

Verify replay and export the evidence

  1. In a recommendation result, find Versions, source, and integrity or the evidence controls near the bottom of the result.
  2. Click Verify replay. Inspect the verification of the recorded result, explanation, and projection when shown.
  3. Click Download JSON evidence. Open the file in a text editor to inspect the version references, preserved input, result, and content hashes.
  4. For an NFR review, use Download evidence with assessments to include the recorded destination, decisions, and adapted copies. You can reopen runs through Runs and history → Run history.

Expected result: replay verification succeeds for the recorded run and the evidence downloads as JSON.

Replay checks reproducibility with the recorded dependencies and a compatible implementation. It does not measure recommendation quality or the suitability of an adapted artifact.

Session, permissions, and administrative features

The reviewer can create and edit business-data copies, run classification, review results, and publish demonstration configurations inside ICSE 2027 Reviewer Workspace. Sign out is available at the bottom of the navigation. Sign in again if the session expires.

Access and audit is an administrator area for listing workspace members, changing their roles/activity, and inspecting business/access audit events. It is hidden for this reviewer login, and its API is blocked. The reviewer cannot enumerate other users, grant permissions, or switch into other users’ organizations. These controls do not need to be enabled to follow this guide.

Understand the results

What you seeWhat it means
Classification labelsFunctional taxonomy labels assigned to a story. Review status indicates whether human attention is required.
Nearest project / storyThe reference record selected under the configured comparison policy.
Similarity & distanceA profile comparison under the selected method and weights. Similarity is not a probability of correctness, risk occurrence, or usefulness.
Feature contributionsHow individual configured features contribute to the comparison.
Accepted / adapted artifactA human decision and a separate contextual revision, with links to the source recommendation.
Verified replayThe recorded result is reproducible with preserved dependencies and a compatible implementation.

Data, limitations, and interpretation

  • Story texts, tasks, project profiles and existing NFRs are reused from our project data. Practice stories are separate copies. Original wording, including Portuguese stories, is retained where applicable.
  • Risk associations and team-distribution values in the controlled comparison are synthetic demonstration examples. The guide does not present them as observed risks or an accuracy evaluation.
  • Local preview is a rule-based mode. Model committee requires working external providers. The complete core walkthrough can be performed without a new external model call.
  • A missing compatible publication is an availability constraint. Test-case retrieval currently lacks its prepared catalog/definition/dataset; no output is invented for that area.
  • Similarity, confidence, dashboard totals and verified replay serve different purposes. None alone establishes empirical correctness or improved productivity.
  • The reviewer login is shared. Counts, queue contents and practice-version names may change. Create a fresh story copy or use an unused version to repeat an exercise independently.

Troubleshooting and repeatable exercises

The Review Queue is empty

Create a new P03 copy of the grade-consolidation story and classify it with Local preview and taxonomy 1.0.0. It should require review. A prepared pending copy may already have been reviewed by another evaluator.

Confirm classification is disabled

Wait for the taxonomy and review context to load. Select valid labels and click Add pair. At least one valid pair must appear under Pairs to confirm.

The story does not appear in Classification history

A saved draft belongs to the project but has no classification yet. Use its Classify story link and complete the run. Clear the history search to see all current classifications.

I changed the taxonomy but the old labels stayed the same

Existing results retain their recorded taxonomy. A project’s taxonomy selection applies to future classifications. Reclassify a practice copy if you want to evaluate the new version.

A provider call fails

Use Local preview for the classification/review exercise and the already classified original stories for recommendation exercises. Inspect provider failures when available; do not treat an unavailable committee as a successful model run.

The risk neighbor differs from the guide

Use definition 2 and dataset 2 with the exact target values in the risk quick start. Between the controlled runs, change only Team distribution.

An accepted NFR is absent from Linked NFRs

The main NFR exercise binds acceptance to This run’s preserved input. To materialize a link to an operational story, explicitly select Selected US-Agent story, review its destination and justification, and confirm it before acceptance. The original recommendation and any adapted copy remain separate artifacts.

I cannot open user management or another organization

This is the expected restriction for the reviewer account. Its application workflows use only the prepared isolated workspace.

# Observer guide

Complete the methodological review and installation check before inviting or observing anyone. The protocol is a proposal until an authorized human records its review. Use a fresh material namespace for each attempted task, a separate training namespace, and an organization authorized for this study. No production accounts or application logins establish a participant sample.

Share only the participant directory. Keep answer keys and expected results separate. Register planned attempts and assign the six task orders before collection. Use pseudonyms; keep names/consent/recordings outside the repository under the reviewed custody policy.

Record start at zero, checkpoints, distinct errors/retries, help, configuration/code changes, pauses/resumes and explicit finish. Record observations, not guessed durations. Completed requires every task-specific checkpoint. Preserve unsuccessful attempts and explanations. A task not started has an attempt-register entry and no session/time value.

Export actual publication envelopes, run JSON and replay reports into the evidence directory. Record byte hashes and reference snapshot hashes. Check provenance/ownership/chronology manually; a successful hash check does not certify human completion. The CLI checks bytes/envelopes and replay linkage, not truthfulness or approval.

Before the final study, audit the pilot, keep deviations, and create a new version if procedure changes. Review relevance separately and independently of the recommended output. Never derive human results or relevance labels from the answer key.
